# Project Brief

## Goal

Build white label personal portfolio and technical blog using Next.js, Payload
CMS, TypeScript, PostgreSQL, and Tailwind CSS.

The public website should be professionally designed. The Payload CMS
administration interface should remain as close as possible to Payload's
official default experience.

## First user

Airton is the only administrative user.

Public visitors include recruiters, employers, technical professionals, and
potential consulting clients.

## Essential workflow

1. User signs in through Payload admin.
2. User creates a draft post.
3. The draft is not public.
4. User publishes the post.
5. The post appears on the public blog.
6. User can update the post later.

## MVP content

- Users
- Posts
- Categories
- Tags
- Media
- Projects
- Basic site settings

## Public pages

- Home
- About or portfolio
- Projects
- Blog
- Individual article
- Basic category or tag filtering
- Contact links

## Important constraint

Use Payload's built-in CMS and admin capabilities.

Do not rebuild or replace the Payload admin layout, navigation, login,
collection screens, rich-text editor, media library, or draft controls.

Customize only the public website unless an approved requirement cannot be met
through Payload configuration.

## Deferred

- Multi-tenancy
- White-label templates
- Customer onboarding
- Theme editor
- Custom domains
- Billing
- Memberships
- Comments
- Reader accounts
- Private content
- Multi-author approval workflow
- Restaurant models
- SaaS dashboard
- AI features
- Microservices
- Kubernetes
- Production Terraform

The future SaaS idea should be recorded only as future direction and must not
create MVP phases or speculative abstractions.

## Roadmap constraint

The MVP roadmap should contain no more than six implementation phases.

Do not implement anything until the revised requirements and roadmap have been
reviewed.
